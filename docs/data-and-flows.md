# 데이터와 화면 간 연결

프로토타입에는 서버가 없습니다. 각 화면은 예시 데이터를 코드 안에 갖고 있고, 사용자가 새로 등록·변경한 것만 브라우저 `localStorage`에 저장해 다른 화면과 나눕니다. 실제 시스템에서는 아래 키가 API·테이블이 될 자리입니다.

## 저장 키

모든 키는 `abt:` 접두어를 붙여 저장합니다(테마만 예외). 값은 JSON입니다.

| 키 | 값의 모양 | 쓰는 화면 | 읽는 화면 |
| --- | --- | --- | --- |
| `abt-theme` | `'dark'` 또는 `'light'` | 모든 화면 | 모든 화면 |
| `abt:guides` | `Guide[]` — 새로 등록한 가이드만(기본 8명 g1–g8은 코드 안) | 가이드·차량 | 가이드·차량, 배정 캘린더 |
| `abt:vehicles` | `Vehicle[]` — 새로 등록한 차량만(기본 8대 v1–v8은 코드 안) | 가이드·차량 | 가이드·차량, 배정 캘린더 |
| `abt:offs` | `{ [가이드·차량 id]: Off[] }` | 가이드·차량, 가이드 내 일정(g3) | 가이드·차량, 배정 캘린더, 가이드 내 일정 |
| `abt:events` | `Event[]` — 새로 등록한 행사만 | 행사 등록 | 행사 목록, 행사 등록(순번), 배정 캘린더 |
| `abt:scheduleOps` | `Op[]` — 배정 캘린더에서 한 작업 순서대로(되돌리기에 씀) | 배정 캘린더 | 배정 캘린더 |
| `abt:assign` | `{ [행사코드]: { guide?, vehicle? } }` — 값은 `'tentative'`(가배정) 또는 `'changed'`(변경 확인 필요) | 배정 캘린더 | 행사 목록 |
| `abt:manuals` | `Manual[]` — 매뉴얼 전체 목록. 키가 없으면 `tools/screens/shared_data.py`의 예시 6건에서 시작 | 매뉴얼, 가이드 브리핑 | 매뉴얼, 가이드 브리핑 |
| `abt:guideReplies` | `{ [행사코드]: 'ok' \| 'declined' }` — 가이드의 배정 수락·어려움 | 가이드 내 일정 | 가이드 내 일정, 배정 캘린더 |

로그인 화면의 「예시 데이터로 되돌리기」는 `abt:`로 시작하는 키를 모두 지웁니다(테마는 남김).

### 레코드 모양

```ts
type Guide = {
  id: string;            // 'gx' + 시각 기반 문자열
  name: string; phone: string;
  lang: string;          // 예: '한국어·영어'
  spec: string;          // 전문 상품
  contract: string;      // 계약 형태: '프리랜서' | '정규'
  rate: string;          // 가이드비(일, MNT) — 숫자만 담은 문자열
  grade: 'A' | 'B' | 'C';
  invite: boolean;       // 가이드 앱 초대 문자 발송
};

type Vehicle = {
  id: string;            // 'vx' + 시각 기반 문자열
  name: string;          // 예: '푸르공 4호차'
  type: string;          // 차종 — 정원·연비 기본값을 정함
  plate: string; cap: number; driver: string; phone: string;
  owner: string;         // 소속 업체
  insurance: string;     // 보험 만료일 'YYYY-MM-DD'
  fuel: number;          // L/100km
};

type Off = { from: string; to: string; why: string };   // 'YYYY-MM-DD', 사유

type Event = {
  code: string;          // 'MN2610-025'
  agency: string;
  product: string; productName: string; short: string;   // 상품코드·이름·캘린더용 짧은 이름
  nights: number;
  arrive: string; depart: string;                         // 'YYYY-MM-DD'
  pax: number; lead: number;                              // 여행객, 인솔자
  owner: string;                                          // 담당
  sales: number; cost: number;                            // 판매금액(KRW), 예상 지상비(MNT, 상품 단가 × 인원 + 고정비)
  created: string;                                        // 'MM.DD'
};

type Op =                                                  // kind: 'guide' | 'vehicle'
  | { kind; type: 'add'; to: string; item: Bar }           // 한 줄에 막대 추가
  | { kind; type: 'addMany' | 'set'; code: string; items: Array<{ to: string; item: Bar }> }   // 행사 배정·변경(to = 줄 id)
  | { kind; type: 'move'; code: string; from: string; to: string; state: 'changed' };          // 다른 사람·차로 옮김

type Manual = {
  id: string;            // 'MA-014'
  title: string;
  cat: '공통 문화' | '장소별' | '상품별' | '여행사별' | '인수인계';
  link: string;          // 연결 대상(모든 행사, 장소, 상품, 여행사)
  tags: string[]; pins: string[];                         // 핵심 주의사항(항상 맨 위)
  sections: Array<{ h: string; b: string }>;
  photos: string[];
  ver: number;
  status: 'draft' | 'review' | 'published';               // 작성 중 · 검토 중 · 게시
  author: string; reviewer: string; updated: string;
  acked: string[];                                        // 이 버전을 확인한 가이드
  change?: { title: string; body: string };               // 상세에 보이는 최근 변경 안내
  live?: { ver: number; title: string; pins: string[]; sections: Array<{ h: string; b: string }>; updated: string } | null;
                                                          // 새 버전을 쓰는 동안 가이드에게 계속 보이는 게시본
};
```

`Bar`는 캘린더 막대(`ScheduleGrid`의 item: 시작 칸, 길이, 라벨, 상태)입니다. 자세한 것은 `design-system/components/index.d.ts`의 `ScheduleItem`을 보세요.

### 동기화

각 화면은 `storage` 이벤트를 듣고 `abt:` 키가 바뀌면 다시 그립니다. 캔버스에서는 화면마다 같은 출처의 iframe이라 한 화면에서 저장한 내용이 열려 있는 다른 화면에 바로 보입니다. `localStorage`를 쓸 수 없으면 그 화면 안에서만 상태로 유지합니다.

## 화면 간 흐름

1. **가이드·차량 등록** — 가이드·차량에서 등록하면 배정 캘린더에 새 줄로 생기고 배정 후보가 됩니다.
2. **불가일** — 가이드·차량 화면이나 가이드 앱 내 일정에서 등록하면 캘린더에 회색 막대로 표시되고 그 기간에는 후보에서 빠집니다. 가이드 앱은 간바타르(g3) 기준입니다.
3. **행사 등록** — 저장한 행사는 행사 목록 맨 위(「새로 등록」)와 캘린더의 미배정 행사 목록에 나옵니다. 가이드는 한국어 가이드 1명, 차량은 여행객 + 인솔 + 가이드 1명만큼 좌석이 필요합니다.
4. **배정** — 캘린더에서 배정하면 `scheduleOps`·`assign`에 남고, 행사 목록의 배정 상태가 가배정 또는 변경 확인 필요로 바뀝니다.
5. **가이드 답변** — 가이드 앱에서 「배정 수락」하면 캘린더 간바타르 줄의 막대가 가이드 확인(실선)으로, 「어려움」이면 변경 확인 필요(「어려움 전달」)로 바뀝니다.
6. **매뉴얼** — 작성 → 검토 요청 → 게시. 게시된 매뉴얼 중 연결 대상이 그 행사에 해당하는 것(모든 행사, 상품, 여행사, 방문 장소)이 가이드 브리핑 「연결된 매뉴얼」에 붙습니다. 가이드가 「읽었습니다」를 누르면 매뉴얼 화면의 가이드 확인에 기록됩니다. 예시 가이드 브리핑(MN2609-038)에 연결되는 대상은 모든 행사, 테를지 승마·게르 2박 3일, 제이원트래블, 테를지 리버 캠프, 칭기즈칸 국제공항입니다.

이 밖의 화면(비용 승인, 송금, 입금, 과입·차감, 정산, 클레임 등)은 처리 결과를 그 화면 안에서만 유지합니다. 화면을 다시 열면 예시 상태로 돌아갑니다.

## 업무 규칙

프로토타입 화면에 들어가 있는 규칙입니다. 상태 단어와 표기 규칙의 원문은 `design-system/README.md`에 있습니다.

**행사·배정**
- 행사코드는 `MN` + 연도 2자리 + 도착 월 2자리 + `-` + 순번 3자리입니다(예: MN2610-025). 순번은 도착 월마다 이어지고, 새 행사는 「예약」 상태로 시작합니다.
- 인원은 여행객+인솔자로 씁니다(예: 18+1명).
- 배정 상태: 미배정 · 가배정(점선) · 배정 확정 · 변경 확인 필요 · 가이드 확인 · 일정 충돌 · 배정 불가. 한 줄에서 날짜가 겹치면 일정 충돌로 자동 표시합니다.
- 차량은 여러 대를 골라 배정합니다. 날짜별 좌석 합계 중 가장 작은 값이 필요 좌석 이상일 때만 배정되고, 인원은 큰 차부터 나눠 표시합니다.

**돈**
- 금액은 원래 통화(KRW·USD·MNT)로 적고, 환산액에는 적용 환율과 적용일을 붙입니다. 소수는 USD 2자리, KRW·MNT 0자리이고 음수는 U+2212(−)로 씁니다.
- 비용 승인: 비용 등록 → 운영 확인 → 회계 검토 → 권한자 승인 → 지급·정산 반영. 300,000 MNT 미만은 회계 검토로 확정합니다. 중복 청구·단가 차이·증빙 누락은 판정이 아니라 「검토 후보」로 보여 줍니다.
- 송금: 요청 · 검토 중 · 승인(아직 안 보냄, 점선) · 일부 송금 · 송금 완료 · 반려. 송금증이 붙은 「송금 완료」만 실선입니다. ABT 한국 → ABT Mongolia LLC 송금은 내부거래라 통합 매출에서 뺍니다.
- 입금: 여행사 청구와 실제 통장 입금을 따로 기록하고, 예상 잔금만으로 입금 완료 처리하지 않습니다. 입금 1건을 여러 행사에 배분할 수 있고, 청구보다 많이 들어온 돈은 과입으로 잔액 원장에 남습니다.
- 잔액 원장(과입·차감): + 는 우리가 돌려줄 돈, − 는 받을 돈입니다. 상계·환불에는 처리 근거가 필요하고, 잔액이 0이 되면 닫힙니다.
- 정산·마감: 월을 마감한 뒤 바꾸려면 재개방을 요청하고 승인받아야 합니다.

**매뉴얼**
- 작성 중 → 검토 중 → 게시. 검토 요청에는 본문 1섹션 이상과 「개인 정보를 넣지 않았습니다」 확인이 필요하고, 연락처나 고객 이름처럼 보이는 내용이 있으면 경고합니다.
- 게시본을 고치면 새 버전(v+1)이 생기고, 게시하기 전까지 가이드에게는 이전 게시본이 보입니다. 새 버전을 게시하면 가이드 확인을 처음부터 다시 받습니다.

**권한·기록**
- 예시 사용자: 이도윤(대표), 김지훈(운영관리자), 박서연(회계담당자), 간바타르(가이드).
- 비용 승인·송금·정산 화면의 「보기 권한」, 대시보드의 「보기 역할」로 역할별 화면을 바꿔 볼 수 있습니다(시연용이며 실제 권한 검사는 없음).
- 관리자·회계 계정은 2단계 인증을 씁니다. 가이드는 회사 마진·정산과 다른 가이드 정보를 볼 수 없습니다.
- 감사 로그에는 금액·승인·마감·권한·로그인·다운로드가 변경 전후 값·사유·승인자와 함께 남고, 기록은 수정·삭제할 수 없습니다.
- 시간은 한국·몽골이 섞이는 곳에 KST/ULAT를 붙이고, 현장에서 생긴 일은 현지(ULAT) 시각으로 기록합니다.

## 실제 시스템으로 옮길 때

- `abt:` 키 자리를 API로 바꿉니다. 지금 코드 안에 있는 예시 데이터(행사, 가이드, 차량, 비용, 입금, 송금, 클레임 등)도 같은 API에서 와야 합니다.
- 행사 상세는 예시 한 건(MN2609-033)뿐이므로 행사코드로 불러오도록 바꿔야 합니다.
- 로그인·2단계 인증·역할 권한·감사 로그는 서버에서 처리합니다. 화면의 권한 전환은 시연용입니다.
- 영수증·송금증·사진 첨부는 파일 이름만 다루는 자리 표시입니다.
- 알림(기한 초과 재알림, 확인 요청 등)은 화면 문구로만 있고 실제 발송은 없습니다.
