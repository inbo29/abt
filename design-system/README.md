ABT Ops는 ABT 여행 운영·정산 통합 관리 시스템(관리자 웹, 가이드 모바일 웹)의 디자인 시스템이다. 행사 한 건을 기준으로 배정, 현장, 비용, 송금, 정산이 이어지는 화면에서 숫자와 상태를 잘못 읽지 않게 하는 것이 목적이다. 사용자는 대표, 운영팀, 회계팀(PC)과 현장 가이드(스마트폰)다.

## 원칙

1. **색은 정산·리스크 상태에만 쓴다.** `progress`(진행·대기), `positive`(정상·확정), `attention`(주의), `critical`(위험) 4색은 상태 전용으로 선점한다. 버튼, 메뉴, 링크, 선택 표시, 차트 막대는 무채색(`action`, `ink`, `surface-selected`, `chart-actual`)으로 칠한다. 화면에 색이 보이면 확인할 것이 있다는 뜻이어야 한다.
2. **점선은 예상, 실선은 확정이다.** 예상 금액, 요청, 가배정, 승인 전 비용, 미입금 청구처럼 아직 실제가 아닌 값은 점선(`line-strong` 또는 상태색 dashed)으로 그린다. 확정·완료·실제 지출은 실선과 채움으로 그린다. 금액, 배지, 배정 막대, 예산 바, 차트에 같은 규칙을 적용한다. 점선을 장식이나 격자선에 쓰지 않는다.
3. **행사코드가 기준이다.** 행사코드는 모든 목록, 원장, 알림에서 `EventCode`(`code` 스타일) 하나의 모양으로 보이고, 누르면 행사 상세로 간다.
4. **원래 통화와 환산액을 함께 보인다.** 금액은 원거래 금액에 통화코드(KRW·USD·MNT)를 붙여 적는다. 환산액에는 적용 환율과 적용일을 붙인다. 집계 화면은 집계 기준 시각, 통화, 환율을 `caption`으로 밝힌다.
5. **경고는 판정이 아니라 검토 후보다.** 중복, 단가 차이, 초과는 "후보", "확인 필요"라고 쓴다. "부정", "오류"로 단정하지 않는다.
6. **요약에서 원장으로 간다.** KPI와 경고에는 해당 행사, 원장, 증빙으로 바로 가는 링크를 둔다.

## 글쓰기

- 짧은 존댓말 평서문을 쓴다. 안내와 오류는 "~해 주세요", "~할 수 없습니다"로 쓰고 사과하지 않는다. 무엇이 잘못됐고 어떻게 고치는지 적는다.
  - 오류: "환율 적용일이 거래일보다 늦습니다. 거래일 이전 환율을 선택해 주세요."
  - 빈 상태: "이 기간에 배정된 행사가 없습니다. 기간을 바꾸거나 행사를 등록하세요."
  - 경고: "중복 청구 후보: 같은 업체·날짜·금액의 식사 비용이 2건 있습니다."
- 버튼은 행동 이름으로 쓴다: "송금 요청", "승인", "반려", "임시저장", "제출", "엑셀 다운로드". 한 행동의 이름은 흐름 끝까지 같다. "송금 요청" 버튼을 누르면 상태는 "요청", 알림은 "송금 요청이 접수되었습니다"가 된다.
- 상태 단어는 아래 표의 단어만 쓴다(`StatusBadge`가 같은 표를 갖고 있다).
- 숫자는 천 단위 쉼표를 찍고, 음수는 "−"(U+2212)로 쓴다. 소수 자리는 USD 2자리, KRW·MNT 0자리다. 표의 금액은 오른쪽 정렬하고 `tabular-nums`를 쓴다. 손실은 `critical` 글자로 쓴다(적자 = 붉은 글자).
- 날짜는 "2026.10.01 (목)", 짧게 "10.01(목)"으로 쓰고, 시간은 24시간 "14:30"으로 쓴다. 한국과 몽골이 섞이는 곳은 시간대를 붙인다: "07:30 ULAT", "08:30 KST". 현장에서 생긴 일은 현지(ULAT) 시각으로 기록한다.
- 인원은 "18+1명"(여행객+인솔자)으로 쓴다.
- 이모지와 느낌표를 쓰지 않는다. 몽골어 번역을 고려해 라벨은 짧게 쓰고 폭을 고정하지 않는다.

| --- | --- |

송금 "승인"은 점선이다. 요청이나 승인만으로는 완료로 보지 않고, 증빙이 붙은 "송금 완료"만 실선이다.

## 색

- 다크가 기본 테마이고 라이트는 같은 역할의 값을 갖는다. 라이트는 야외에서 쓰는 가이드 화면과 출력용 화면에 쓴다. 테마는 상위 요소의 `data-theme="light"`로 바꾼다.
- 바탕은 `bg`(작업 영역 뒤), `surface`(패널·표·사이드 메뉴), `surface-raised`(드롭다운·시트), `surface-sunken`(입력, 표 머리줄, 코드 칩) 순으로 쌓는다. hover는 `surface-hover`, 선택은 `surface-selected`로 표시한다.
- 글자는 `ink`(본문·확정 금액)와 `ink-muted`(라벨, 통화코드, 시간대, 예상 금액) 두 단계만 쓴다. `ink-faint`는 비활성 전용이다.
- 상태색은 글자(`progress` 등)와 옅은 바탕(`progress-soft` 등)이 한 쌍이다. 배지·알림·KPI는 `*-soft` 바탕에 상태색 글자를 쓰고, 4.5:1 이상을 지킨다. 채움이 필요할 때(진행 중 행사, 긴급 클레임, 반려 버튼)만 상태색 바탕에 `on-progress`·`on-critical` 글자를 쓴다.
- 4색은 색각 이상에서도 서로 구분되도록 밝기와 색상을 함께 벌렸다. 그래도 모든 상태는 단어를 같이 쓴다. 색만으로 상태를 전하지 않는다.
- 주 버튼은 `action`(다크에서는 밝은 무채색, 라이트에서는 검정) 채움이다. 화면당 하나만 둔다.

## 타이포그래피

- 글꼴은 IBM Plex Sans(라틴·숫자·몽골어 키릴), IBM Plex Sans KR(한글), IBM Plex Mono(식별자)다. `--font-sans`, `--font-mono`로 쓴다.
- 관리자 웹: 화면 제목 `title-1`, 패널 제목 `title-2`, 소제목 `title-3`, 본문 `body`, 표 칸 `cell`, 라벨·열 머리글 `label`, 메타 정보 `caption`, KPI 값 `kpi`를 쓴다.
- 가이드 모바일: `m-title`, `m-body`(16px), `m-label`, `m-caption`을 쓴다.
- `code`(Plex Mono)는 행사코드, 송금번호 같은 식별자에만 쓴다. 일반 라벨에 쓰지 않는다.
- 세로로 줄 서는 숫자(표, 축)는 `tabular-nums`를 쓰고, 혼자 크게 서는 숫자(KPI)는 비례 숫자를 쓴다. KPI의 원화는 "4,820만", "4.86억"처럼 줄여 쓴다.

## 간격·밀도·레이아웃

- 4px 단위(`space-1`~`space-12`)를 쓴다. 패널 안쪽은 `space-4`, 패널 사이와 작업 영역 좌우는 `space-6`, 화면 머리와 본문 사이는 `space-8`이다.
- 관리자 웹은 1440px 화면에 맞춘다. 왼쪽에 `SideNav`(`sidebar-width`)를 두고 오른쪽 작업 영역은 표가 폭을 다 쓰게 한다. 화면 머리는 제목(`title-1`)과 집계 기준(`caption`)을 왼쪽에, 행동 버튼을 오른쪽에 둔다. 필터는 표 위 한 줄(`Select` inline, `control-sm`)에 두고 그 줄이 아래 모든 표·차트에 적용된다.
- 표 행은 `row-regular`(40px), 원장과 감사 로그는 `row-compact`(32px)다. 버튼·입력 높이는 `control-md`(34px)이다.
- 가이드 모바일은 390px 폭에 좌우 `space-4` 여백을 둔다. 화면 루트에 `abt-mobile` 클래스를 붙이면 컴포넌트 글자가 모바일 크기(15–16px)로 커진다. 버튼과 입력은 `size="lg"`(`control-lg`, 48px)를 쓰고 하단에 `MobileTabBar`(`tabbar-height`)를 둔다. 오늘 해야 할 일과 현장 등록을 첫 화면 위쪽에 둔다. 모바일 카드와 시트는 `radius-lg`이다.

## 테두리·그림자·모서리

- 다크에서는 테두리(`line`)로 면을 나누고, 그림자는 떠 있는 레이어(`shadow-lg`)에만 쓴다. 라이트의 패널은 `shadow-sm`을 쓸 수 있다.
- 모서리는 계층마다 다르다: 컨트롤·배지·코드 칩 `radius-sm`(4), 패널·표·드롭다운 `radius-md`(6), 모바일 카드·시트 `radius-lg`(12), 개수 표시·단계 점 `radius-full`.
- 입력과 체크박스 테두리는 `line-strong`(3:1 이상)이다. `line`은 장식용 구분선에만 쓴다.

## 상태와 상호작용

- hover는 `surface-hover`, 선택은 `surface-selected`, 비활성은 45% 불투명도로 표시한다. 선택에 색을 쓰지 않는다.
- 키보드 포커스는 `focus-ring`(바탕색 2px 틈 + `ink` 2px 실선)이다. 모든 버튼, 링크, 입력에 같은 링을 쓴다.
- 마감된 자료는 입력을 막고 "마감" 표시와 재개방 안내를 함께 보인다(`TextField` locked).
- 움직임은 상태가 바뀔 때 색·테두리 전환 120ms ease-out만 쓴다. 장식 애니메이션과 진입 효과는 쓰지 않고, `prefers-reduced-motion`이면 전환도 끈다.

## 차트

- 실제 값 막대·선은 `chart-actual`(무채색), 예상·예산은 `chart-expected` 점선 테두리로 그린다. 기준을 넘은 부분만 `attention`·`critical`로 칠한다.
- 격자선과 축은 `chart-grid` 실선 1px이다. 점선은 예상 전용이므로 격자에 쓰지 않는다.
- 막대는 24px 이하로 얇게, 선은 2px로 그린다. 축은 하나만 쓰고(이중 축 금지), 단위가 다른 두 값은 차트를 나눈다.
- 글자는 차트 색이 아니라 `ink`, `ink-muted`로 쓴다. 모든 차트에는 같은 값을 담은 표를 함께 둔다.

## 아이콘

- 아이콘은 메뉴에만 쓴다: `SideNav`, `MobileTabBar`. 버튼, 배지, 알림, KPI, 표에는 넣지 않고 단어로 쓴다.
- 기능 표시만 예외다: 드롭다운 화살표(`Select`), 표 정렬 표시(`DataTable`).
- 세트는 Lucide(ISC 라이선스)이고 선 굵기 1.75, 메뉴 18px, 모바일 탭 22px이며 글자색을 따른다. `Icon`에 이름으로 넣는다. 새 메뉴 아이콘이 필요하면 Lucide에서 같은 굵기로 추가한다.
- ABT 로고 파일은 아직 없다. 로고 자리에는 "ABT Ops"를 `--font-sans` 700으로 쓴다.

## 컴포넌트 쓰는 법

- 컴포넌트는 `window.Abt`에 있다(React 18 필요). 불러오는 순서: Google Fonts → `tokens.css` → `components/bundle.css` → React 18 → ReactDOM 18 → `components/bundle.js`.
- 글꼴 링크: `https://fonts.googleapis.com/css2?family=IBM+Plex+Mono:wght@400;500;600&family=IBM+Plex+Sans+KR:wght@400;500;600;700&family=IBM+Plex+Sans:wght@400;500;600;700&display=swap`
- 상태 단어는 직접 쓰지 말고 `StatusBadge`에 `axis`와 `status`를 넘긴다. 같은 표가 `Abt.STATUS`에 있다.
- 금액은 `Money`, 행사코드는 `EventCode`, 시각은 `DateTime`으로 쓴다. 이 셋은 `DataTable` 열의 `type`(`money`, `code`, `datetime`)으로도 쓸 수 있다.
- 화면의 배치(패널, 머리, 여백)는 이 문서의 토큰으로 직접 짠다. 컴포넌트는 위의 목록에 있는 것만 쓴다.
